CURIX 서비스 프로세스 소개

버전: MVP v1.0  ·  작성일: 2026.03.25  ·  분류: 내부 공유용

CURIX는 사용자가 관심 토픽을 입력하면, 관련 콘텐츠를 자동 수집하고 AI가 편집하여 맞춤형 브리프 레터를 생성해주는 서비스입니다.

1. 서비스 개요

기존 뉴스레터는 발행자가 토픽을 선정하고, 독자는 수동적으로 소비합니다. CURIX는 이 구조를 뒤집어, 독자가 토픽을 지정하면 AI가 실시간으로 콘텐츠를 수집·편집하여 개인화된 브리프 레터를 즉시 제공합니다.

핵심 가치

  • 온디맨드 생성 — 원하는 주제를, 원하는 스타일로, 원하는 시점에
  • 다중 소스 수집 — 웹 검색 + RSS 피드를 통합하여 폭넓은 정보 확보
  • AI 편집 — 단순 나열이 아닌, 맥락과 인사이트가 있는 레터 생성

2. 전체 프로세스

1

토픽 & 설정 입력

사용자가 관심 토픽(예: "AI 규제 동향")을 입력하고, 레터 스타일·톤·분량을 선택합니다.

사용자 입력
2

콘텐츠 수집 (병렬 실행)

웹 검색 (Tavily API) — 토픽 기반 고급 검색으로 관련 웹 콘텐츠 10건을 수집합니다. 본문 전체를 포함하여 깊이 있는 정보를 확보합니다.

RSS 피드 수집 — 등록된 미디어(TechCrunch, OpenAI Blog, Byline Network 등)에서 토픽 키워드와 매칭되는 최신 기사를 필터링합니다.

Tavily API RSS Parser
3

데이터 정제

수집된 콘텐츠를 통일된 형식으로 변환하고, URL 기준 중복 제거 후 최신순으로 정렬합니다.

중복 제거 날짜순 정렬
4

AI 브리프 레터 생성

정제된 콘텐츠와 사용자 설정을 Gemini AI에 전달합니다. AI는 원문을 자기 말로 재작성하고, 출처를 명시하며, 설정에 맞는 구조와 톤으로 브리프 레터를 편집합니다.

Gemini 2.5 Flash 프롬프트 엔지니어링
5

결과 렌더링

생성된 레터(JSON)를 마크다운 → HTML로 변환하여 웹 페이지에 표시합니다. 제목, 태그, 읽기 시간, 섹션별 본문, 출처 링크가 포함됩니다.

Markdown 렌더링

4. 사용자 설정 옵션

스타일 (persona_type)

옵션설명
요약형핵심만 추출. 불릿 포인트 위주. 항목당 1~3문장.
인사이트형배경 맥락 + "왜 중요한가" 분석 + 향후 전망. 섹션 간 논리적 흐름 연결.
큐레이션형각 콘텐츠를 독립적 추천 아이템으로 구성. 제목 + 한줄 소개 + 추천 이유 + 원문 링크.

톤 (tone)

옵션설명
친근한구어체. "~인데요", "~거든요" 허용. 이모지 사용 가능.
전문적인격식체(합니다/습니다). 전문 용어와 데이터 인용.
간결한최소 단어. 불릿 포인트·숫자 중심.

분량 (reading_time)

옵션섹션 수글자 수
3분 이내2~3개1,200~1,500자
5분 이내3~5개2,000~2,500자
10분 이상5~8개4,000~5,000자

8. 실행 방법

  1. .env 파일에 TAVILY_API_KEY와 GEMINI_API_KEY 설정
  2. npm install 실행
  3. npm run dev로 개발 서버 실행 (코드 변경 시 자동 재시작)
  4. 브라우저에서 http://localhost:3000 접속
  5. 토픽 입력 → 설정 선택 → "레터 생성하기" 클릭

11. AI 프롬프트 전문

아래는 레터 생성 시 Gemini 2.5 Flash에 실제로 전달되는 시스템 프롬프트입니다. 사용자가 선택한 설정(스타일·톤·분량)과 수집된 콘텐츠가 이 프롬프트와 함께 AI에 입력됩니다.

11-1. 시스템 프롬프트 (System Instruction)

당신은 CURIX의 브리프 레터 편집 AI입니다. 수집된 콘텐츠를 편집해서 개인맞춤형 브리프 레터를 만듭니다. 핵심 규칙: 1. 원문을 그대로 베끼지 마세요. 반드시 자기 말로 다시 쓰세요. 2. 모든 정보에 출처 링크를 [텍스트](URL) 형태로 넣으세요. 3. 반드시 "인트로 → 본문 섹션들 → 아웃트로" 구조를 지키세요. 4. 한국어로 작성하세요. personaType별 스타일: [요약형] - 핵심만 추출. 불릿 포인트 위주. 항목당 1~3문장. [인사이트형] - 배경 맥락 + "왜 중요한가" 분석 + 향후 전망 포함. - 섹션 간 논리적 흐름 연결. [큐레이션형] - 각 콘텐츠를 독립적 추천 아이템으로 구성. - 형식: 제목 + 한줄 소개 + 추천 이유 + 원문 링크. tone별 문체: [casual] 구어체. "~인데요", "~거든요" 허용. 이모지 가능. [professional] 격식체(합니다/습니다). 전문 용어 + 데이터 인용. [concise] 최소 단어. 불릿 포인트·숫자 중심. reading_time별 분량: "3분 이내": 섹션 2~3개, 총 1,200~1,500자 "5분 이내": 섹션 3~5개, 총 2,000~2,500자 "10분 이상": 섹션 5~8개, 총 4,000~5,000자 출력은 반드시 아래 JSON만 반환: { "title": "레터 제목 (20자 이내)", "subtitle": "한줄 요약", "topic_tags": ["태그1", "태그2"], "reading_time_minutes": 5, "intro": "인트로 마크다운 텍스트", "sections": [ { "type": "insight 또는 summary 또는 curation", "title": "섹션 제목", "content": "섹션 본문 마크다운" } ], "outro": "아웃트로 마크다운 텍스트" }

11-2. 유저 프롬프트 템플릿 (매 요청 시 동적 생성)

아래 수집된 콘텐츠를 기반으로 브리프 레터를 작성해주세요. ━━━━━━━━━━━━━━━━━━━━ 사용자 설정 ━━━━━━━━━━━━━━━━━━━━ - 페르소나: {{persona_type}} - 톤: {{tone}} - 읽기 시간: {{reading_time}} ━━━━━━━━━━━━━━━━━━━━ 수집된 콘텐츠 ({{count}}건) ━━━━━━━━━━━━━━━━━━━━ [콘텐츠 1] - 제목: {{title}} - 출처: {{source}} ({{source_type}}) - URL: {{url}} - 본문: {{content}} --- [콘텐츠 2] ... ━━━━━━━━━━━━━━━━━━━━ 지시사항 ━━━━━━━━━━━━━━━━━━━━ 위 콘텐츠를 바탕으로 사용자 설정에 맞는 브리프 레터 1건을 생성하세요. JSON만 반환해주세요. 다른 텍스트 없이 JSON만 출력하세요.

11-3. 프롬프트 설계 원칙

원칙설명
전문 복제 금지 원문 재게재 없이 변형적 요약만 허용. 저작권 리스크 최소화.
출처 투명성 모든 정보에 원문 링크 필수 첨부. 독자가 원문 확인 가능.
파라미터 분기 personaType × tone × reading_time 조합에 따라 스타일·문체·분량이 자동 분기.
JSON 강제 출력 프론트엔드에서 파싱 가능하도록 구조화된 형식으로만 응답.
소스 유형 인식 web(웹 검색) / rss(피드) 등 소스 특성에 맞는 처리 방식 적용.
